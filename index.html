The problem

Fraud is rare but costly. A model that always answers "legitimate" is about 99.8% accurate and detects nothing. This project addresses four gaps:

  • Misleading metrics: models are judged by PR-AUC (primary), recall, precision, F1, MCC and ROC-AUC.
  • Data leakage: duplicates removed, scaler fitted on training data only, class weights instead of oversampling, test set untouched until final reporting.
  • Default thresholds: the 0.5 cut-off is tuned on a validation set (selected: 0.416).
  • Model choice: linear baseline, bagging, boosting and an unsupervised detector compared on identical splits.

Limitations

  • V1 to V28 are PCA-anonymised, so predictions cannot be explained in business terms (merchant, location).
  • Two days of data only; real fraud patterns drift over time.
  • Only 95 frauds in the test set, so metrics have high variance. Results come from the quick 60-tree run.
  • Latency, training time and memory use have not been measured yet.
  • Built for learning and demonstration, not production fraud screening.

Training runs in Python, not in the browser

The report designs this page to launch training from the dashboard. A static web page cannot run scikit-learn, so use the command line, which produces everything the dashboard shows:

python -m venv venv
venv\Scripts\activate          # macOS/Linux: source venv/bin/activate
pip install -r requirements.txt
python train.py --fast         # 60-tree Random Forest, reported run
python train.py                # full run, 150 trees
pytest -q                      # 5 tests: schema, preprocessing, training, inference, threshold

What train.py does

  1. Load dataset (284,807 rows)
  2. Drop duplicates and missing values (283,726 rows)
  3. Feature engineering: Hour, Log_Amount; RobustScaler fitted on train only
  4. Stratified split: 64% train / 16% validation / 20% test
  5. Train 4 models with balanced class weights (train set)
  6. Select best model by validation PR-AUC
  7. Tune the decision threshold: maximise F1 on validation set
  8. Final evaluation on the untouched test set
  9. Save pipeline + threshold; export metrics and plots

Interpretation

Random Forest has the best PR-AUC (0.815) and precision (0.945): only 4 of 56,651 legitimate transactions were flagged, but about 27% of frauds (26 of 95) were missed. Logistic Regression has higher recall (0.768) and ROC-AUC (0.965) but a clearly lower PR-AUC (0.683). Ranking by ROC-AUC alone would have picked it, which is why PR-AUC is the better criterion here. Isolation Forest has a high ROC-AUC (0.935) yet very low precision and F1, so labelled supervision matters.

With 95 test frauds, each metric can move by several points with a different split or seed. ROC and precision-recall curve traces are not included in the linked repository, so they are not drawn here.
